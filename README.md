# 댕순 (daengsoon) — 같이 보는 불멍

모르는 사람들과 **모닥불 주위에 앉아**, 태우고 싶은 걸 태우는 곳.
말은 필요 없습니다. 누가 사직서를 태우면 옆 사람 화면에서도 불이 확 타오릅니다.

## 들어오면

1. **"당신은 누구신가요?"** 성별(남/여)과 나이대(10대~60대)를 고릅니다. 매번 묻되 지난 선택은 미리 채워 둡니다.
   캐릭터의 머리 모양·머리색·키가 그에 따라 조금씩 다릅니다. (세부 꾸미기는 나중에)
2. **산 또는 바다**를 고릅니다. 둘 다 저녁입니다.
   - 🏔️ 산: 산 실루엣, 숲, 반딧불. 귀뚜라미 소리
   - 🌊 바다: 수평선, 물결, 모래사장. 파도 소리
   환경음은 불소리보다 작게 깔립니다. 전부 파일 없이 합성합니다.

## 한 방(캠프)의 구조

- 4인 화로 4개 + 1인 화로 4개 = **20석**, 정원 20명
- 방 id는 `종류-번호`: `mountain-01`, `sea-03`. 종류별로 따로 채워집니다
- 캐릭터를 클릭/탭/방향키로 움직이고, 통나무를 누르면 앉습니다
- **앉으면 카메라가 그 화로로 들어갑니다.** 불과 같은 화로에 앉은 사람들만 크게 보이고,
  옆 사람이 뭘 태우면 그 모션이 그대로 보입니다. 일어나면 다시 넓은 뷰로 돌아옵니다.
- 폰 세로 화면이 기준입니다. 앉은 상태에선 땅을 잘못 눌러도 일어나지 않습니다(일어나기 버튼으로만)
- 앉으면 태울 수 있습니다: 보고서, 사직서, 편지, 영수증, 시험지, 일기장
- 태워도 불이 세지진 않습니다. **순간적인 연출**만 모두에게 보입니다
- 방이 차면 자동으로 다음 캠프가 열립니다. `?room=sea-03` 으로 특정 캠프에 갈 수 있습니다

## 그림은 3D입니다 (three.js)

비유하면 종이에 그린 그림이 아니라 **미니어처 세트를 카메라로 찍는 것**입니다.
- **하늘**: Poly Haven의 360도 사진(HDRI). 배경이자 조명. 산은 해질녘(B1)·늦은 밤 마을 불빛(B9), 바다는 별밤(B12)·달밤(B6). 22시 이후엔 늦은 밤 하늘로 바뀝니다.
- **땅**: Poly Haven PBR 텍스처. 가을엔 낙엽(forest_floor), 바다는 모래(coast_sand_01). 계절별 텍스처는 `three/config.ts`의 표 한 줄로 추가합니다.
- **캐릭터**: 파일 없이 기본 도형으로 깎은 A1(Quaternius) 느낌의 2.5등신. 걷기·대기·앉기는 코드로 움직입니다. 진짜 모델(GLB)이 오면 `three/character.ts`만 교체.
- **화로·그루터기·나무·먼 산·바다**: 전부 저폴리 기본 도형. 불은 입자(Points) + 실제 빛(PointLight)이라 사람과 땅을 비춥니다.
- 모든 재료는 **CC0**(저작권 표시조차 불필요). `apps/client/public/assets/` 약 13MB, 방 종류별로 필요한 것만 받습니다(첫 로딩 약 5MB).

카메라는 둘입니다. 걸을 땐 비스듬히 위에서 따라가고, 앉으면 **어깨 너머에서 불을 바라봅니다**. 건너편 사람이 불 너머로 보입니다.

## 코드 구조

```
daengsoon/
├─ apps/
│  ├─ client/   브라우저 (Vite + TypeScript + Canvas 2D)
│  │  └─ src/
│  │     ├─ main.ts    입력·HUD·네트워크 연결을 묶는 곳
│  │     ├─ world.ts   3D 캠프장 전체를 지휘 (서버 상태 → 캐릭터·불·소품)
│  │     ├─ three/
│  │     │  ├─ scene.ts      렌더러, 하늘(HDRI), 땅(PBR), 안개, 달빛
│  │     │  ├─ config.ts     월드↔미터 비율, 계절별 땅, 시간별 하늘(밝기 정규화)
│  │     │  ├─ character.ts  코드로 깎은 캐릭터 + 걷기/앉기 애니메이션
│  │     │  ├─ fire.ts       입자 불꽃 + 흔들리는 빛 + 태우기 플래시
│  │     │  ├─ props.ts      화로, 그루터기, 나무, 먼 산, 바다
│  │     │  ├─ camera.ts     걷기 카메라 / 어깨 너머 앉기 카메라
│  │     │  └─ fx.ts         태우기 연출(날아가는 물건, 재)
│  │     ├─ socket.ts  서버와의 전화선 (자동 재연결)
│  │     └─ audio.ts   소리 합성 (파일 없음)
│  └─ server/   Node.js + WebSocket
│     └─ src/
│        ├─ room.ts    캠프 하나의 시뮬레이션. 바깥 세상(WebSocket)을 모름
│        ├─ rooms.ts   매표소: 방 만들기, 자동 배정, 빈 방 정리
│        └─ index.ts   HTTP(정적 파일, /api/rooms) + WebSocket 연결
└─ packages/
   └─ shared/   양쪽이 함께 쓰는 규칙서: 화로·자리 좌표, 프로필, 캠프 종류, 태울 것 목록, 메시지 형식
```

### 핵심 원칙

1. **서버가 심판입니다.** 브라우저는 "저기로 갈래요", "여기 앉을래요"라고 말만 합니다.
   걷는 속도, 자리가 비었는지, 쿨다운은 서버가 판단합니다. 그래서 모두가 같은 장면을 봅니다.
2. **스냅샷 + 델타.** 들어올 때 방 전체를 한 번 받고(`welcome`), 그 뒤로는 바뀐 사람만 받습니다(`update`).
   서버는 20Hz로 계산하고 10Hz로만 보냅니다.
3. **방은 독립된 덩어리.** `Room` 클래스는 WebSocket을 모릅니다. 메시지를 받고 `client.send`로 보낼 뿐이라
   나중에 Cloudflare Durable Objects 같은 "방 하나 = 서버 조각 하나" 구조로 옮기기 쉽습니다.
4. **부드러운 화면.** 서버 좌표를 그대로 찍지 않고 lerp로 따라갑니다. 10Hz 데이터가 60fps처럼 보입니다.

## 실행

```bash
pnpm install
pnpm dev        # 서버(8787) + 화면(5173) → http://localhost:5173
```

창을 여러 개 열어 보세요. 같은 캠프에 모입니다.

```bash
pnpm build && pnpm start   # 서버 하나가 전부 서빙 → http://localhost:8787
```

## 배포

`Dockerfile`로 Fly.io, Railway, Render 등 **긴 연결을 유지할 수 있는** 곳에 올립니다.
(Vercel 같은 서버리스는 WebSocket을 오래 못 잡아두므로 맞지 않습니다.)
